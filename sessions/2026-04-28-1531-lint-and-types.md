## Summary

Drove ruff and mypy to zero from the P0 baseline (5 lint, 12 typecheck).
The lint errors were straightforward (`l` → `line`, import ordering, an
E402 caused by side-effect setup in `test_tools.py`). The big mypy win
was switching `scripts/check.sh` to invoke tooling via `python -m`: the
previous baseline ran a system-level `mypy` from `~/.local/bin` that
couldn't see the venv's `pydantic` / `prompt_toolkit`, producing nine
import-not-found errors that vanished once mypy ran in the right env.
The remaining genuine errors (untyped decorator args, an `Any`-return
from `json.loads`) were fixed properly rather than silenced.

## Changes

- `daemon/tools/edit.py` — renamed ambiguous `l` loop var to `line` (E741 x2).
- `daemon/tools/__init__.py` — sorted imports per ruff I001. The
  side-effect tool imports come first; submodules import the registry
  directly so initialisation order is unaffected.
- `daemon/tests/conftest.py` — new file. Hoisted the YOLO test setup out
  of `test_tools.py` so imports can sit at the top of the test module.
- `daemon/tests/test_tools.py` — removed the pre-import YOLO mutation
  (E402 x2).
- `daemon/cli/prompt.py` — typed the keybinding handlers with
  `prompt_toolkit.key_binding.key_processor.KeyPressEvent`, fixing the
  untyped-decorator and missing-annotation errors.
- `daemon/core/api.py` — annotated the `json.loads` result so mypy
  doesn't flag a returned-`Any`.
- `scripts/check.sh` — invoke `pytest` / `ruff` / `mypy` via `python -m`
  so the quality gate runs against the venv where `pydantic` and
  `prompt_toolkit` are installed. Without this the baseline misreports.
- `ROADMAP.md` — moved P1 to Done with this breadcrumb's filename.

## State of the application

Runtime behaviour is unchanged — `python -m daemon` still launches the
configure flow on first run and the REPL once an API key is set. The
quality gate is now a tight ratchet: any regression in tests, lint, or
typecheck shows up on the next `./scripts/check.sh`.

One process note for the next agent: if you see lint/type errors that
look implausibly large, sanity-check that `python -m ruff` / `python -m
mypy` are pulling from the venv with `pip install -e ./daemon[dev]`
applied. The check script handles this now, but invoking the tools
directly may not.
