# 2026-04-30 18:17 UTC — Diff display for write/edit

**Phase:** P7 — Diff display
**Status:** landed

## Summary

Until now `write` and `edit` returned the bare string `"ok"` after
mutating a file. Both the user (via the `⎿  …` preview) and the model
(via the tool message) saw the same uninformative ack, so neither knew
what actually changed without running `read` again. This session
replaces that ack with a unified diff: the pre-image already captured
for `/undo` is paired with a freshly-read post-image, fed to
`difflib.unified_diff`, and the result is hung off the tool call. The
preview line now reads `+N -M`, and the model receives the diff body
verbatim so it can reason about the change without re-reading the
file.

The tool implementations themselves are unchanged — they still return
`"ok"`, which keeps `daemon/tests/test_tools.py` honest. The diff is
applied one layer up, in `_run_turn`, where the pre-image is already
in scope.

## Changes

- `daemon/core/diff.py` — new module. `format_diff(path, pre, post)`
  decodes both halves as UTF-8, returns `"ok (no change)"` when they
  match (covers `write` overwriting with identical content and `write`
  of `""` into a missing file), `"ok (binary)"` if either side isn't
  valid UTF-8, and otherwise a `+N -M` summary line followed by the
  unified-diff body. `pre=None` is treated as empty so brand-new files
  diff cleanly.
- `daemon/cli/main.py` — `_run_turn` calls a new `_diff_result` helper
  on every successful `write`/`edit`. The helper reads the post-image
  and hands `(pre, post)` to `format_diff`; if the post-image read
  fails (file moved/unlinked between tool call and read) it falls back
  to the original tool result so we never crash the turn.
- `daemon/tests/test_diff.py` — new file, 9 tests: new-file diffs,
  modifications, no-change, missing→empty no-change, binary on either
  side, pure-addition / pure-deletion counts, and the diff header
  carrying the path through.
- `ROADMAP.md` — moved P7 (Diff display) from **Later** to **Done**.

## State of the application

After every successful `write` or `edit`, the REPL preview now shows
something like:

```
⏺ Edit(daemon/cli/main.py)
  ⎿  +3 -1
```

…and the model receives the full unified diff (with `--- path` /
`+++ path` headers and `@@` hunks) as the tool result, so the next
turn can describe or react to the change without re-reading the file.

`/undo` behaviour is unchanged — the pre-image used for diffing is the
same one pushed onto the checkpoint stack. Read-only tools (`read`,
`grep`, `glob`, `bash`, `task`) still return their existing strings;
only `write` and `edit` are diffed.

Special results worth knowing:
- `ok (no change)` — the post-image equals the pre-image (e.g. a
  `write` that re-writes identical bytes, or a `write ""` into a
  missing file).
- `ok (binary)` — one of the halves isn't valid UTF-8. We don't try
  to render binary diffs.
- If the post-image read itself fails, the tool's original `"ok"` is
  preserved.

## Open questions / risks

- The unified diff goes to the model in full. For huge edits this
  could balloon the context window. We could cap the body at, say,
  500 lines and append `... (truncated)` — but in practice models
  ground on the diff, so I left it uncapped for now. Revisit if a
  user complains about token bills.
- `format_diff` decodes as UTF-8. Files in other encodings (latin-1,
  shift-jis) will be reported as `ok (binary)`. That's the same
  guarantee `read` makes elsewhere — consistent, even if a touch
  conservative.
- The diff uses the file path (as passed to the tool) for both `---`
  and `+++` headers. Standard `git`-style diffs use `a/path` and
  `b/path`; we don't, because the path the model passed isn't always
  repo-relative. Easy to revisit if someone wants to pipe these
  through `patch`.
