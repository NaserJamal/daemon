# 2026-05-06 07:30 UTC — Debug-mode API logging

**Phase:** P8 — Logging / debug mode
**Status:** landed

## Summary

Added an opt-in debug log that captures every chat-completion request
and the assembled response to a JSONL file, so users can inspect what
`daemon` actually sends and receives without reaching for `tcpdump` or
a proxy. Streaming and non-streaming code paths share one log point —
the streaming response is logged as the final assembled payload, which
matches what the rest of the harness sees.

The feature is off by default and has zero cost when disabled (one `is
None` check per call). Enable it three ways:

- `daemon --debug` — writes to `./daemon-debug.log`
- `daemon --debug=path/to/file` — writes to that path (also accepted as
  `--debug path/to/file`)
- `DAEMON_DEBUG=1` (truthy) or `DAEMON_DEBUG=path` env var — same as
  the flag, used when no flag is passed

The banner gains a `debug → <path>` tag when active so it's obvious
the file is being written.

## Changes

- `daemon/core/debug.py` — new module. Module-level path slot guarded
  by a lock; `enable(path=None)` / `disable()` / `is_enabled()` /
  `current_path()` manage it. `log_event(kind, data)` appends one JSON
  line `{"ts", "kind", "data"}` and silently no-ops when disabled or
  on `OSError` (logging must never crash the REPL). `from_env()`
  honours `DAEMON_DEBUG`.
- `daemon/core/api.py` — `call_api` logs `request` (url + body) before
  `urlopen`, `response` after a successful read (post-assembly for
  streaming), and `http_error` (status + body) on `HTTPError`. The
  Authorization header is never logged.
- `daemon/cli/main.py` — `_consume_debug_flag` strips
  `--debug` / `--debug=path` / `--debug path` from argv and enables
  logging; falls back to `from_env()` if no flag was given. Banner
  shows the active log path when on.
- `daemon/tests/test_debug.py` — new file, 15 tests covering the
  module surface, env-var parsing, the api.py wrap point (logged and
  not-logged paths), and the CLI flag parser (bare, `=value`,
  `value` as next arg, env fallback, no-op).
- `ROADMAP.md` — moved "Logging / debug mode" from **Later** to
  **Done** as P8.

## State of the application

`daemon` now has a clean inspection hook for API traffic:

```
$ daemon --debug
daemon | gpt-4o-mini | https://api.openai.com/v1 | /home/x | debug → /home/x/daemon-debug.log

> hi

$ tail daemon-debug.log
{"ts":"...","kind":"enabled","data":{"path":"..."}}
{"ts":"...","kind":"request","data":{"url":"...","body":{"model":"...","messages":[...]}}}
{"ts":"...","kind":"response","data":{"choices":[...],"usage":{...}}}
```

Each line is parseable JSON, so `jq -c .data.body.messages[-1]` or a
quick `python -c "import json; ..."` is enough to spot a misbehaving
turn. Errors from the upstream HTTP call land as `http_error` records
*before* the `RuntimeError` propagates, so a dropped key or 429 is
visible without re-running.

The Authorization header is *not* logged. The body is — which means a
debug log will contain user prompts and tool results. Users who want
to share one should redact accordingly; we don't try to scrub it for
them.

4. **`/debug` slash command.** Toggle the log mid-session without

## Open questions / risks

- Debug-log output is unbounded — long sessions can produce big files.
  Considered adding rotation but skipped it; users who care can `rm`
  or `mv` the file between runs since `enable()` opens in append mode.
- Streaming responses are logged once after assembly, not chunk-by-
  chunk. That's intentional (we want to log what the rest of the code
  actually sees), but it means a stream that hangs mid-flight will
  leave a `request` with no matching `response` or `http_error`.
  Acceptable: the gap is itself a useful signal.
- `DAEMON_DEBUG` is the only env var; we deliberately did not add a
  config-file knob. Debug logging is a transient diagnostic, not a
  long-lived setting, so making it sticky in the user config would
  invite accidental token-bill shock.
