# 2026-05-07 09:00 UTC — Web fetch tool

**Phase:** P9 — Web fetch tool
**Status:** landed

## Summary

Added a `fetch` tool that lets the model GET an http(s) URL and read the
response body as text. It uses stdlib `urllib.request` only (no new
dependencies). HTML is reduced to readable text via a small `HTMLParser`
subclass that drops `<script>`, `<style>`, and other non-content tags
and inserts paragraph breaks. Bodies are capped at 1 MB by default
(override with `max_bytes`), and the existing safety-confirmation flow
is reused: outside of YOLO mode the user sees the URL and approves it
before any network request leaves the harness. Errors (HTTP, DNS,
timeout, OS-level) are returned as strings — the tool never raises.

## Changes

- `daemon/tools/fetch.py` — new `FetchTool`. Validates scheme/host,
  reuses `safety.confirm` (so YOLO bypasses the prompt), opens the URL
  with a 30 s timeout, reads `max_bytes + 1` bytes to detect truncation,
  honours `Content-Type` `charset=` (falling back to UTF-8 on unknown
  encodings), and runs HTML through a private `_TextExtractor`
  (`HTMLParser` subclass) that drops script/style/head, breaks block
  tags, and collapses whitespace.
- `daemon/tools/__init__.py` — added `fetch` to the side-effect import
  list so the registry picks it up.
- `daemon/tests/test_fetch.py` — new file, 14 tests: plain text, HTML
  stripping, truncation marker, unsupported scheme, missing host,
  HTTPError / URLError / TimeoutError mapping, charset decoding, bogus
  charset fallback, user-denied path, registry presence, and three
  unit tests for the HTML extractor.
- `ROADMAP.md` — moved "Web fetch tool" from **Later** to **Done** as
  P9.

## State of the application

The model can now pull text content from the web through a single new
tool. Example call shape:

```
fetch(url="https://example.com/")          # returns body text, max 1 MB
fetch(url="https://example.com/", max_bytes=50_000)
```

Behaviour:

- Schemes other than `http`/`https` (e.g. `file://`, `ftp://`,
  `gopher://`) are rejected before any I/O happens.
- A confirmation prompt with reason `"network fetch to <host>"` runs
  for every URL unless `YOLO=1` is set in the user config — same gate
  the bash tool uses for dangerous commands.
- HTML responses are reduced to text. Non-HTML responses are returned
  as-is (decoded by the response's declared charset, UTF-8 fallback).
- A response longer than `max_bytes` is truncated and the tool appends
  a single `(truncated at N bytes)` footer so the model knows it
  didn't see the full body.

There are no new env vars and no new config keys; the safety prompt
key is the existing `YOLO` flag.

## Open questions / risks

- The HTML→text pass is intentionally simple: it strips tags, drops
  script/style/head, and collapses whitespace. Pages that put their
  content inside JS-rendered shells will return mostly empty text.
  Adding a heavier dependency (e.g. `readability-lxml`) would help
  but breaks the "few dependencies" pitch — left for a later phase if
  it actually bites.
- No per-host or per-session rate limit. A model can call `fetch` in
  a loop. The confirmation prompt is the only brake when YOLO is off;
  with YOLO on, nothing stops it. Worth revisiting if we see abuse.
- The confirmation prompt asks once per call. There is no "always
  allow this host" memo. For now that matches how `bash` confirms.
